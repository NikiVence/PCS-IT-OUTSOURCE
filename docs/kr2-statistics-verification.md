# КР 2: статистика, экспорт и проверка запуска

Дата проверки: 12.10.2026. Среда: Windows 11, Temurin JDK 21.0.12.1,
Maven 3.9.9, PostgreSQL 17, JavaFX 21.0.2.

## Реализация

- Экран: `src/main/resources/ru/mirea/project/view/statistics-view.fxml`.
- Контроллер: `src/main/java/ru.mirea.project/ui/StatisticsController.java`.
- Открытие: кнопка «Статистика» в `MainController`.
- Данные: все записи `LinkedHashMap<String, Number>` из
  `ServiceRequestService.getStatistics()`, с названиями и порядком сервиса.
  Репозиторий возвращает шесть `Long` и один `Double` — среднюю оценку.
- Сохранение: JavaFX `FileChooser` → существующий `ExcelExportService.export()`.
  Постоянного пути сохранения в коде нет; пользователь выбирает его в диалоге.
- Загрузка и экспорт выполняются через JavaFX `Task`; элементы интерфейса
  обновляются в JavaFX-потоке. Ошибки показываются через `AlertHelper`.
- Общая архитектура, модели и схема БД не изменялись.

## Автоматические проверки

Для обычного локального Maven-кэша параметр `-Dmaven.repo.local` можно убрать.
Все команды выполняются из корня проекта.

```powershell
mvn -B "-Dmaven.repo.local=.m2/repository" "-Dit.gui=true" test
```

Результат: **BUILD SUCCESS**, 21 тест обнаружен, 19 выполнены успешно,
2 пропущены по условиям запуска (старый интеграционный тест с изменением БД
и отдельный новый GUI-тест с реальной БД).

Покрытие выполненного прогона:

- Существующие бизнес-правила, фильтрация и сортировка заявок.
- Содержимое Excel: три листа, типы ячеек, даты, пустые значения,
  текст вместо формул, экспорт пустой БД.
- Отказ от перезаписи файла, неверное расширение, добавление `.xlsx`
  при отсутствии расширения и ошибка записи в недопустимый каталог.
- Загрузка реального FXML, семь строк статистики, формат средней оценки `4,50`.
- Экспорт из контроллера с проверкой всех семи показателей в созданном Excel.
- Отмена выбора файла без чтения экспортных данных и без создания файла.
- Ошибка обновления БД: очистка устаревших показателей и успешный повтор.
- Ошибка БД при экспорте: сообщение об ошибке, файл не создаётся.

```powershell
mvn -B "-Dmaven.repo.local=.m2/repository" "-Dit.gui=true" "-Dit.gui.database=true" "-Dtest=StatisticsControllerTest" test
```

Результат: **BUILD SUCCESS**, все **7 тестов выполнены успешно**. Проверены
старт `ItOutsourceApplication`, загрузка главного окна и экрана заявок,
переход в статистику, семь показателей и экспорт из текущей PostgreSQL.
Число строк листов пользователей и заявок сверено с сервисами; лист статистики
содержит семь показателей и заголовок. Этот тест только читает БД.

В воспроизводимых JUnit GUI-тестах выбор файла и сообщения заменены
тестовыми обработчиками. Они требуют графическую сессию (`-Dit.gui=true`).
Обычный `mvn test` не запускает GUI и интеграционные проверки.
Старый `DatabaseIntegrationTest` не запускался: он требует отдельной новой
тестовой БД и изменяет данные, поэтому его нельзя запускать на рабочей базе.

## Проверка настоящего диалога

Дополнительно выполнен локальный сценарий с настоящим окном приложения,
настоящим `FileChooser` и автоматическим вводом пути через AWT Robot:

1. Запуск главного окна и переход в «Статистику».
2. Загрузка показателей из текущей PostgreSQL.
3. Нажатие «Экспорт в Excel», ввод нового пути в системном диалоге, сохранение.
4. Получение сообщения «Экспорт завершён» с путём к файлу.
5. Открытие созданного `.xlsx` через Apache POI: три листа, семь показателей.

Результат: **NATIVE_EXPORT_OK**. Проверочный отчёт создан в
`target/native-export-1791792729346.xlsx` (локальный артефакт, не входит в Git).
Временный сценарий `target/NativeExportSmoke.java` также не входит в Git.
В базе во время проверки ничего не создавалось и не изменялось.

## Сценарий для демонстрации

1. Подготовить PostgreSQL и `db.properties` по README; запустить `mvn javafx:run`.
2. Показать начальный экран заявок и перейти в «Статистику».
3. Для неизменённого seed сверить: 6 пользователей, 12 заявок, 3 новые,
   5 активных, 2 закрытые, 3 высокого приоритета, средняя оценка 4,50.
   В небольшом окне таблицу можно прокрутить до последней строки.
4. Нажать «Обновить»; дождаться окончания загрузки.
5. Нажать «Экспорт в Excel» и отменить диалог: файл не должен появиться.
6. Повторить экспорт, выбрать доступный каталог и новое имя `.xlsx`.
7. Проверить сообщение об успехе и открыть файл в Excel или LibreOffice:
   листы «Пользователи», «Заявки», «Статистика», числовые значения и даты.
8. Повторить с тем же именем: приложение сообщает, что файл уже существует,
   и сохраняет предыдущий отчёт без изменений.

Значения seed применимы только к исходной базе. Экспорт читает все данные;
фильтры на экране заявок его не ограничивают. Сервисы читают пользователей,
заявки и статистику отдельными запросами: при одновременном редактировании
другими клиентами единый транзакционный снимок не гарантируется.
