# PCS-IT-OUTSOURCE

Консольная система технической поддержки на Java для КР 1. Пользователи и заявки хранятся в PostgreSQL; работа с данными выполняется через JDBC.

## Готовность по требованиям КР 1

| Требование | Реализация |
|---|---|
| Две связанные сущности, enum | `User`, `ServiceRequest`, четыре перечисления |
| CRUD пользователей и заявок | Создание, чтение, изменение и удаление через меню |
| Минимум 5 бизнес-правил | Проверки в сервисах, список ниже |
| Два поиска | По части заголовка и описания без учёта регистра |
| Два фильтра | По статусу и приоритету |
| Две сортировки | По дате создания (новые первыми) и приоритету (HIGH → LOW) |
| Минимум 5 показателей статистики | 7 показателей в отдельном пункте меню |
| Excel .xlsx | Пользователи, заявки и статистика на трёх листах |
| Интерфейс и полиморфизм | `CrudRepository<T>`, две JDBC-реализации, зависимости сервиса от интерфейса |
| Просмотр таблиц БД | Отдельный пункт меню для `users` и `requests` |
| SQL и тестовые данные | Каталог `sql`: создание БД, схема, 6 пользователей и 12 заявок |
| Документация для защиты | Эта инструкция, [ER-диаграмма](docs/er-diagram.md), [пример Excel](docs/example-export.xlsx) |

## Требования для запуска

- JDK 17 или новее.
- Maven 3.9 или новее.
- PostgreSQL (проверено на версии 17).
- Доступ к Maven Central при первой сборке для загрузки зависимостей.

Зависимости: PostgreSQL JDBC 42.7.2, Apache POI 5.2.5; тесты — JUnit 5.

## Подготовка базы данных

Выполните из корня проекта, заменив `postgres` на своего пользователя PostgreSQL:

```shell
psql -h localhost -U postgres -d postgres -v ON_ERROR_STOP=1 -f sql/create_database.sql
psql -h localhost -U postgres -d it_outsource -v ON_ERROR_STOP=1 -f sql/schema.sql
psql -h localhost -U postgres -d it_outsource -v ON_ERROR_STOP=1 -f sql/seed.sql
```

В DataGrip/pgAdmin сначала выполните `create_database.sql` в подключении к `postgres` вне транзакции. Затем переключитесь на `it_outsource` и выполните `schema.sql`, после него `seed.sql`. Скрипты рассчитаны на первоначальную установку: повторно поверх заполненной БД их запускать не нужно. Seed использует ID, назначенные в новой базе.

Если база была создана старой версией проекта с полем `password_hash`, выполните один раз:

```shell
psql -h localhost -U postgres -d it_outsource -v ON_ERROR_STOP=1 -f sql/migrate_remove_user_password.sql
```

Начальные данные: 6 пользователей (1 ADMIN, 3 CLIENT, 2 EXECUTOR), 12 заявок, все 5 статусов и 4 категории. Клиенты имеют ID 2, 3, 6; исполнители — 4, 5.

Скопируйте шаблон настроек. Для PowerShell:

```powershell
Copy-Item src/main/resources/db.properties.example src/main/resources/db.properties
```

Для Linux/macOS:

```shell
cp src/main/resources/db.properties.example src/main/resources/db.properties
```

В `src/main/resources/db.properties` задайте свои реквизиты:

```properties
db.url=jdbc:postgresql://localhost:5432/it_outsource
db.user=YOUR_USERNAME
db.password=YOUR_PASSWORD
```

Этот файл исключён из Git. Приложение читает его из classpath; после изменения настроек снова выполните `mvn compile`.

## Сборка и запуск

```shell
mvn test
mvn compile exec:java
```

В IntelliJ IDEA откройте `pom.xml` как Maven-проект, выберите JDK 17+ и запустите `ru.mirea.project.Main`. В консоли должна использоваться UTF-8.

Главное меню:

```text
1. Пользователи
2. Заявки
3. Поиск, фильтрация и сортировка
4. Статистика
5. Экспорт заявок и статистики в Excel
6. Вывести таблицы базы данных
0. Выход
```

Операции возвращают в меню. Неверное число, отсутствующий ID, нарушение бизнес-правила и ошибки SQL выводятся как сообщения. Если при запуске отсутствует конфигурация подключения, приложение сообщает причину и завершает работу.

## Экспорт

Выберите пункт **5** и введите, например, `reports/it-outsource.xlsx` без кавычек. Путь может быть абсолютным или относительно каталога запуска; отсутствующие каталоги создаются. Уже существующий файл не перезаписывается — выберите другое имя.

Книга содержит:

- **Пользователи** — ID, логин, ФИО, email, роль, дата создания.
- **Заявки** — все 12 полей, включая описание, ID клиента/исполнителя, даты и оценку.
- **Статистика** — все 7 показателей из меню.

Даты и числа записываются как типизированные ячейки; отсутствующие значения остаются пустыми. Заголовки закреплены, у таблиц включён автофильтр. Выгружаются все текущие записи БД; фильтры из меню поиска не ограничивают экспорт. [Пример для защиты](docs/example-export.xlsx) получен из отдельной PostgreSQL с `schema.sql` и `seed.sql`.

## Архитектура и ООП

```text
ConsoleUI → Service → CrudRepository / JDBC → PostgreSQL
                └→ ExcelExportService → Apache POI → .xlsx
```

- `Main` создаёт сервисы и запускает интерфейс.
- `model` — классы `User` и `ServiceRequest` с private-полями, конструкторами и методами доступа; enum задают роли, категории, статусы и приоритеты.
- `repository` — параметризованные SQL-запросы и преобразование `ResultSet` в модели. Ресурсы JDBC закрываются через try-with-resources.
- `CrudRepository<T>` — общий интерфейс CRUD. `ServiceRequestRepository` расширяет его операциями поиска, фильтрации, сортировки и статистики; JDBC-реализация находится в `JdbcServiceRequestRepository`. В модульных тестах используется реализация в памяти — пример полиморфизма.
- `service` — бизнес-правила и проверки. Поиск, фильтрация, сортировка и статистика выполняются SQL-запросами в repository.
- `ui` — ввод и вывод; SQL-запросов в меню нет.
- `DatabaseManager` — единый объект настройки подключения, выдающий новое `Connection` на операцию.
- `exception` — `BusinessException`, `EntityNotFoundException`, `DatabaseException`.

`PreparedStatement` передаёт значения параметров отдельно от SQL через `?`, в отличие от конкатенации пользовательского ввода в запрос. Поля SQL ENUM преобразуются в Java enum.

## Бизнес-правила

1. При создании пользователя обязательны логин, ФИО, email и роль.
2. Заголовок заявки после удаления пробелов по краям содержит минимум 3 символа, описание обязательно.
3. Категория и приоритет заявки обязательны.
4. Создать заявку можно только для существующего пользователя с ролью CLIENT.
5. Назначить исполнителем можно только существующего пользователя с ролью EXECUTOR.
6. Клиент может изменять только свою заявку и только в статусе NEW.
7. Разрешены переходы `NEW → IN_PROGRESS`, `IN_PROGRESS → WAITING`, `WAITING → IN_PROGRESS`, `IN_PROGRESS → RESOLVED`, `RESOLVED → CLOSED`.
8. При первом переходе в IN_PROGRESS устанавливается время взятия в работу, при CLOSED — время закрытия.
9. Оценить можно только закрытую заявку; оценка — целое число от 1 до 5.

Удаление заявки выполняется физически по ID после подтверждения в меню, как требует CRUD в КР 1. Удаление клиента с заявками запрещает внешний ключ; при удалении исполнителя `executor_id` его заявок становится NULL. Уникальность логина/email и ограничения длины полей дополнительно проверяются БД.

В КР 1 нет экрана входа: меню принимает ID пользователя для операций. Роли используются для бизнес-проверок, а не как полноценная система авторизации.

## Статистика и проверка на защите

Для исходного seed ожидаются: пользователей **6**, заявок **12**, новых **3**, активных (`IN_PROGRESS` и `WAITING`) **5**, закрытых **2**, высокого приоритета **3**, средняя оценка закрытых заявок **4,50**. Если оценок нет, средняя равна 0.

1. Пункт 6: показать обе таблицы; пункт 4: сверить статистику.
2. Пункт 3: поиск `ноутбук` по заголовку и `Чёрный экран` по описанию; фильтры NEW/HIGH и обе сортировки.
3. Создать заявку для клиента 2, найти по ID, изменить её от имени клиента 2, назначить исполнителя 4.
4. Провести заявку по `NEW → IN_PROGRESS → RESOLVED → CLOSED`, поставить оценку 5. Попробовать недопустимый переход и оценку 6.
5. Удалить созданную заявку, проверить отсутствие по ID.
6. Экспортировать .xlsx и открыть три листа; ввести текст вместо числа и убедиться, что меню продолжает работу.

Модульные тесты запускаются `mvn test` без PostgreSQL. Интеграционный тест включается отдельно: `mvn -Dit.database=true test`. Для него нужен `db.properties` в classpath, указывающий **на отдельную тестовую БД**, только что заполненную `schema.sql` и `seed.sql`: тест создаёт и удаляет свои записи, проверяет JDBC, меню и экспорт. Не используйте для него рабочую БД.
