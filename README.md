# IT Outsource

Настольная информационная система для службы технической поддержки. Приложение помогает вести пользователей и заявки клиентов: регистрировать обращения, назначать исполнителей, отслеживать статусы, оценивать выполненные работы и анализировать показатели поддержки.

Интерфейс реализован на JavaFX, данные хранятся в PostgreSQL. Приложение подключается к базе напрямую через JDBC, а PostgreSQL разворачивается в Docker.

## Возможности

- управление пользователями: просмотр, добавление, редактирование и удаление;
- полный CRUD заявок с выбором клиента и исполнителя из существующих пользователей;
- поиск заявок по заголовку и описанию;
- фильтрация по статусу, приоритету и категории;
- сортировка по нескольким параметрам;
- управление жизненным циклом заявки: назначение исполнителя, изменение статуса и выставление оценки;
- проверка введённых данных и понятные сообщения об ошибках;
- статистика по пользователям и заявкам;
- экспорт пользователей, заявок и статистики в `.xlsx` через системный `FileChooser`.

## Быстрый запуск

### 1. Подготовьте окружение

Потребуются:

- JDK 21;
- Maven 3.9 или новее;
- Docker с поддержкой `docker compose`.

### 2. Создайте локальные конфигурационные файлы

Linux/macOS:

```shell
cp .env.example .env
cp src/main/resources/db.properties.example src/main/resources/db.properties
```

PowerShell:

```powershell
Copy-Item .env.example .env
Copy-Item src/main/resources/db.properties.example src/main/resources/db.properties
```

Шаблоны уже согласованы между собой. По умолчанию используются база `it_outsource`, пользователь `it_outsource_app` и порт `55432`. Файлы `.env` и `db.properties` содержат локальные настройки и не должны попадать в Git.

### 3. Запустите PostgreSQL

```shell
docker compose up -d --wait
docker compose ps
```

При первом запуске Docker создаст схему и загрузит тестовые данные из каталога `sql`. Данные сохраняются в именованном volume после остановки контейнера.

### 4. Запустите приложение

```shell
mvn javafx:run
```

JavaFX запускается на компьютере пользователя, а не внутри Docker. Приложение подключается через JDBC к опубликованному порту PostgreSQL.

Остановить базу данных:

```shell
docker compose down
```

Команда не удаляет сохранённые данные. Для полностью чистого запуска можно удалить volume командой `docker compose down -v`, но все локальные данные базы будут потеряны.

## Конфигурация базы данных

Docker читает параметры из `.env`:

```dotenv
POSTGRES_DB=it_outsource
POSTGRES_USER=it_outsource_app
POSTGRES_PASSWORD=it_outsource_local_password
POSTGRES_PORT=55432
```

Java-приложение читает параметры JDBC из `src/main/resources/db.properties`:

```properties
db.url=jdbc:postgresql://localhost:55432/it_outsource
db.user=it_outsource_app
db.password=it_outsource_local_password
```

При изменении имени базы, пользователя, пароля или порта обновите оба файла. Пароль не хранится в Java-классах.

### Запуск без Docker

Если PostgreSQL уже установлен локально, базу можно подготовить вручную:

```shell
psql -h localhost -U postgres -d postgres -v ON_ERROR_STOP=1 -f sql/create_database.sql
psql -h localhost -U postgres -d it_outsource -v ON_ERROR_STOP=1 -f sql/schema.sql
psql -h localhost -U postgres -d it_outsource -v ON_ERROR_STOP=1 -f sql/seed.sql
```

После этого укажите фактические реквизиты подключения в `db.properties`.

## Интерфейс

В главном окне доступны три раздела:

- **Заявки** — таблица обращений, CRUD, поиск, фильтры, сортировка, назначение исполнителя, смена статуса и оценка;
- **Пользователи** — таблица пользователей и операции добавления, изменения и удаления;
- **Статистика** — семь показателей системы и экспорт отчёта в Excel.

Таблицы построены на `TableView` и обновляются через `ObservableList`. Формы создания и изменения открываются в диалоговых окнах, связанные сущности выбираются из списков. Перед удалением приложение запрашивает подтверждение.

## Архитектура

```text
View (FXML + CSS)
        ↓
Controller (JavaFX)
        ↓
Service (бизнес-правила)
        ↓
Repository (JDBC)
        ↓
PostgreSQL
```

- `model` — сущности `User`, `ServiceRequest` и перечисления предметной области;
- `ui` — JavaFX-контроллеры, обработка действий пользователя и обновление представления;
- `service` — валидация, бизнес-правила, статистика и экспорт;
- `repository` — CRUD и SQL-запросы к PostgreSQL;
- `exception` — прикладные исключения с сообщениями для пользователя;
- `resources/.../view` — FXML-разметка и CSS-оформление;
- `sql` — создание базы, схема и начальные данные.

SQL не размещён в JavaFX-контроллерах. Контроллеры координируют интерфейс, сервисы отвечают за правила предметной области, а репозитории — за чтение и запись данных.

## Модель данных

Основные сущности:

- `User` — пользователь с ролью `CLIENT`, `EXECUTOR` или `ADMIN`;
- `ServiceRequest` — заявка с категорией, приоритетом, статусом, клиентом и необязательным исполнителем.

Каждая заявка принадлежит одному клиенту и может быть назначена одному исполнителю. Подробная схема связей и ограничений приведена в [ER-диаграмме](docs/er-diagram.md).

Допустимые переходы статусов:

```text
NEW → IN_PROGRESS ⇄ WAITING
          ↓
       RESOLVED → CLOSED
```

Оценку от 1 до 5 можно поставить только закрытой заявке.

## Проверка и сборка

Модульные тесты не требуют запущенной базы данных:

```shell
mvn test
```

Сборка проекта:

```shell
mvn clean package
```

Интеграционные тесты запускаются отдельно и работают с базой, указанной в `db.properties`:

```shell
mvn -Dit.database=true test
```

Используйте для них отдельную тестовую базу: интеграционные тесты создают и удаляют записи.

GUI-тесты в графической сессии:

```shell
mvn -Dit.gui=true test
```
